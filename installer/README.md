# Установщик RunneOS

Установка RunneOS с live-образа: `archinstall` с профилем RunneOS и постустановочными
шагами, которые выполняет сам пакет `runneos-config`.

**Статус: реализовано; 2026-10-12 установка впервые пройдена end-to-end в QEMU** — до
графического входа установленной системы ([протокол](../docs/results-install-2026-10-12.md)).
На реальном железе, с интерактивным меню и с LUKS не проверялась. Ниже отдельно указано, что
проверено, а что нет.

## Как пользоваться

С загруженного live-образа RunneOS:

```bash
cd /путь/к/runneos/installer     # на live-образе — из чекаута или из копии
sudo ./runneos-install
```

`runneos-install` проверяет, что в `/etc/pacman.conf` есть раздел `[runneos]` (иначе
пакеты RunneOS не разрешатся), и запускает `archinstall --config user_configuration.json`.
Пароли спрашиваются интерактивно; при необходимости передайте свой файл учётных данных
`--creds creds.json` (формат — `examples/creds-sample.json` из пакета `archinstall`;
такой файл содержит хеши паролей, поэтому в репозиторий он не попадает).

## Состав профиля

`user_configuration.json` задаёт:

| Параметр | Значение | Почему так |
|---|---|---|
| Загрузчик | **Limine** | соответствует замыслу установщика; поддерживается archinstall 4.5 |
| Ядро | `linux` | |
| Звук | PipeWire | стек RunneOS |
| Сеть | NetworkManager | |
| Профиль | `Minimal` + greeter `sddm` | рабочий стол ставим пакетами RunneOS, а не профилем archinstall |
| Подкачка | zram (zstd) | как на рабочей машине |
| Пакеты | 43 пакета: `niri`, `dms-shell`, `quickshell`, `ghostty`, порталы, звук, `snapper` + `snap-pac`, `sddm`, `firefox` и все `runneos-*` | повторяет состав ISO |
| Постустановка | `custom_commands: ["sh -c 'runneos-post-install --apply || echo ВНИМАНИЕ…'"]` | шаги RunneOS выполняет пакет, а не копия скрипта в установщике |

Обёртка `sh -c '… \|\| echo …'` появилась после первой сквозной установки: `archinstall`
выполняет `custom_commands` **до** `genfstab`, и любой ненулевой код возврата обрывает
установку — целевая система остаётся с пустым `/etc/fstab`. Теперь провал постустановочного
шага печатает предупреждение, но не мешает `genfstab` и загрузке.

**Диска в профиле намеренно нет.** `archinstall` спросит устройство сам и попросит
подтверждение перед изменениями. Готовый `disk_config` с LUKS и подтомами btrfs здесь не
положен сознательно: его нельзя проверить в этом окружении, а неверная разметка — самая
дорогая ошибка установщика. На интерактивном шаге выбирайте LUKS и btrfs с подтомами
`@` и `@home`, как на рабочей машине.

## Постустановочные шаги

`runneos-post-install` ставится пакетом `runneos-config` в `/usr/bin` и вызывается
установщиком внутри новой системы. Он идемпотентен и умеет два режима:

```bash
runneos-post-install --check    # только отчёт, ничего не меняет (по умолчанию)
runneos-post-install --apply    # выполнить шаги
```

Что делает:

1. **Настраивает `[runneos]` в `/etc/pacman.conf`.** Это важнее, чем кажется: на
   live-образе репозиторий подключён как `file:///runneos-repo/$arch`, и если оставить это
   в установленной системе, **каждая следующая операция pacman будет падать**. Скрипт
   проверяет, отвечает ли сервер RunneOS, и либо переписывает раздел на его адрес
   (адрес публичного репозитория проекта — тогда обновления работают), либо
   комментирует раздел с объяснением: пакеты `runneos-*` остаются установленными,
   обновлений не будет. Адрес переопределяется `RUNNEOS_REPO_SERVER`; подробности о
   сервере, публикации и подписи — в [справке о репозитории](../.agents/skills/runneos/references/repository.md).
2. **Выбирает дисплей-менеджер** (`sddm`), если он ещё не выбран: пакет
   `runneos-desktop` намеренно не тянет DM, и без этого шага установленная система
   загрузится в консоль.
3. **Снимки:** если конфигурации `snapper` для корня нет, пытается создать её сам и, когда
   это не удаётся, включает юнит `runneos-snapper-firstboot.service` — из установщика
   snapper не видит подтом (корень будущей системы смонтирован как `/mnt/archinstall`), и
   конфигурацию создаёт первый запуск установленной системы; таймеры включаются сразу. На
   не-btrfs корне честно сообщает, что снимки недоступны.
4. **Проверяет профиль `/etc/skel`** — без него у нового пользователя не будет настроек
   Niri и Ghostty.
5. **Проверяет dconf-базу** с темой и иконками WhiteSur.

После первого входа в сеанс DMS нужно выполнить `runneos-install-dms-plugins` — установка
плагинов требует активного сеанса и в постустановку не входит.

## Что проверено

- **Конфигурация разбирается самим archinstall**: `ArchConfig.from_config()` принимает
  файл; разобраны `Limine`, профиль `Minimal` с greeter `Sddm`, ядро `linux`, 43 пакета,
  `custom_commands`, zram, NetworkManager, локаль.
- **`runneos-post-install --check` выполнен на рабочей машине**: отчёт соответствует
  фактическому состоянию (дисплей-менеджер выбран, конфигурация snapper есть, таймеры
  включены, профиль `/etc/skel` на месте, dconf-база собрана, проблем не найдено).
- **`runneos-install`**: синтаксис, справка, проверка root и проверка раздела `[runneos]`;
  на носителе обёртка исполняемая (`0755` через `file_permissions`).
- **Носитель отдаёт `[runneos]`**: в образе есть `/runneos-repo/x86_64` и раздел `[runneos]`
  в live-`/etc/pacman.conf`, поэтому `archinstall` разрешает пакеты `runneos-*` без сети.
- **Установка пройдена end-to-end в QEMU 2026-10-12** (`tests/qemu/`): пустой диск, GPT +
  btrfs, `rc=0`, заполненный `/etc/fstab`, Limine, `sddm`, `/etc/skel`, 606 пакетов в целевой
  системе. Установленная система загружается до SDDM с сессией Niri; `systemctl --failed`
  пуст, конфигурацию снимков создаёт первый запуск, `pacman -Sy` работает с выключенным
  `[runneos]`. [Протокол](../docs/results-install-2026-10-12.md).
- **Поведение при недоступном сервере**: раздел `[runneos]` выключается с объяснением, а не
  оставляет мёртвый `file:///runneos-repo` — проверено песочным стендом и в целевой системе.

## Что не проверено

- **Интерактивное меню `archinstall`** — выбор диска и создание учётных записей: прогон идёт
  по конфигу с `pre_mounted_config` и учётной записью из тестового конфига.
- Шифрование LUKS, установка на реальное железо, первый вход в сеанс DMS и
  `runneos-install-dms-plugins` в свежей системе.
- `pacman -Syu` (полное обновление) после отключения `[runneos]`; проверена только
  синхронизация баз `pacman -Sy`.

## Откат и риски

Установщик стирает выбранный диск — это его основная опасность, и подтверждение
запрашивает `archinstall`, а не этот профиль. Профиль не содержит разметки, поэтому
ошибка в нём не может привести к стиранию без интерактивного подтверждения.
