# RunneOS Agents Firstboot: онбординг провайдеров при первом входе

После установки RunneOS провайдеры агентов (`codex`, `opencode`) стоят, но не
авторизованы: `runneos-agents provider auth-status` честно сообщает «не авторизован».
Этот пакет при **первом входе в сеанс DMS** открывает диалог: что подключено, что нет
и как подключить штатным входом провайдера. Пользователь терминал не ищет — кнопка
«Подключить» открывает `runneos-terminal` с `codex login` / `opencode auth login`.

## Как это работает

- Юнит `/usr/lib/systemd/user/runneos-agents-firstboot.service` включён симлинком в
  `/etc/systemd/user/graphical-session.target.wants/` (тот же приём, что у dms.service):
  стартует с графическим сеансом у любого пользователя.
- Однократность — не в юните, а в маркере
  `~/.local/state/runneos/agents-firstboot/done`: диалог пишет его при закрытии
  (любым способом). Юнит с `ConditionPathExists=!…done` больше не запускается.
- Вернуть диалог: `runneos-agents-firstboot --reset` (маркер убирается) или запустить
  команду вручную в любой момент.
- Кнопка «Подключить» запускает штатную команду входа провайдера в терминале;
  после закрытия терминала окно пересобирается со свежими состояниями.
  **Диалог ничего не авторизует сам и ключей не хранит** — вход выполняет CLI
  провайдера, ключ остаётся у провайдера (у opencode — в его собственной БД).
- «Открыть панель агентов» запускает `runneos-agents-panel`.

## Проверка без дисплея (QEMU, серийная консоль)

```sh
runneos-agents-firstboot --smoke-test   # JSON: {ok, marker, providers:[…]}; код 0/1
runneos-agents-firstboot --reset        # убрать маркер
```

## Границы

- Диалог — вспомогательный экран, не часть ядра `runneos-agents` (ядро ничего не
  запускает само, INTERFACE.md §1). Удаление пакета не влияет на CLI, панель и сеанс.
- Отсутствие `runneos-agents`, провайдеров или дисплея — честный текст, а не падение;
  юнит при сбое не блокирует вход в сеанс.
- Авторизация через GNOME Keyring — модель `runneos-ai-usage` (его карточки-аккаунты);
  здесь она не применяется, потому что CLI провайдеров читают свои собственные
  хранилища, а не keyring.
- Известная особенность провайдера (2026-10-13, opencode v2.0.26): при переопределённом
  `XDG_STATE_HOME` команда `opencode auth list` висит. Наш проверочный таймаут честно
  превращает это в «неизвестно» для opencode (не в ошибку диалога); в обычном сеансе,
  где `XDG_STATE_HOME` стандартный, проверки быстрые (~0,1 с).

## Разработка

```sh
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_firstboot_agents.py' -v
./scripts/build-repo.sh   # сборка пакета вместе с остальными
```

Контракт ядра и адаптеров: `packages/runneos-agents/INTERFACE.md` (v1.4 — авторизация).
