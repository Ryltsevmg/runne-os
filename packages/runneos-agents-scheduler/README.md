# RunneOS Agents Scheduler: расписания задач и уведомления

Периодические задачи агентам: «каждые 30 минут проверь почту», «ежедневно в 09:30
собери отчёт». Исполнение всегда идёт через штатный `runneos-agents ask` — ход
проходит через все ворота агента (доступность, авторизация, политика, песочница),
как любой другой. Пакет существует отдельно, потому что ядро `runneos-agents`
по инварианту ничего не запускает само (INTERFACE §1) — а расписание, по определению,
«само».

## Настройка

```sh
# задача
runneos-agents-scheduler add почта helper --when 'every 30m' --prompt 'проверь почту и скажи, что важного'
runneos-agents-scheduler add отчёт helper --when 'daily 09:30' --prompt 'собери отчёт по воркспейсу' --notify always

# таймер (opt-in: пакет его сам не включает)
systemctl --user enable --now runneos-agents-scheduler.timer

runneos-agents-scheduler list            # задачи и статусы
runneos-agents-scheduler disable почта   # выключить задачу (не удаляя)
runneos-agents-scheduler remove почта
runneos-agents-scheduler run             # выполнить дозревшие вручную (так делает таймер)
```

- `--when` понимает `every Nm` (интервал в минутах) и `daily ЧЧ:ММ`.
- `--notify always|failure|never` — уведомления через `notify-send` (DMS показывает
  их в сеансе). По умолчанию — только о неудаче. Нет notify-send или сеанса — тихо.
- Задача выполняется с пометкой `[по расписанию ID]` в тексте — в журнале агента
  виден источник задачи.
- Конфиг: `~/.config/runneos/agents-schedules.json` (0600), статус последнего
  запуска пишется туда же.

## Границы

- Таймер не включается автоматически: пакет ставит юниты, включает их владелец.
  Без таймера `run` можно вызвать вручную (из юнита, из скрипта, руками).
- Точность: опрос раз в 5 минут (`AccuracySec=30s`) — `daily 09:30` выполнится
  в первом опросе после 09:30, не мгновенно в 09:30:00.
- Пропущенные запуски (компьютер был выключен) не навёрстываются: `daily` выполнится
  в первый опрос следующего дня после рубежа; `every Nm` — при первом опросе, когда
  прошло N минут с последнего запуска.
- Никакой автономии поверх ворот: неудача хода — это статус задачи и уведомление,
  а не ретраи; ворота политик и песочницы действуют как на обычный `ask`.
