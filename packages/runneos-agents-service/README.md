# RunneOS Agents Service: служба очереди задач

Ядро `runneos-agents` по инварианту ничего не запускает само (INTERFACE §1) — поэтому
очередь задач исполняет эта служба: пользовательский юнит, **opt-in**. Ход выполняет
штатный оркестратор ядра: все ворота действуют (доступность, авторизация, политика,
песочница), журнал агента не отличает задачу от обычного `ask`.

## Настройка

```sh
systemctl --user enable --now runneos-agents-service.service

# задачи ставятся из CLI агентов
runneos-agents task add помощник 'собери краткую сводку по воркспейсу'
runneos-agents task list
runneos-agents task show task-xxxx
runneos-agents task cancel task-xxxx
```

Поведение:

- **FIFO**: задачи одного агента выполняются в порядке постановки.
- **Crash-safe**: на старте служба возвращает `running`-задачи в очередь — ход не мог
  пережить смерть процесса, задача могла.
- **Отмена**: `task cancel` помечает задачу; служба замечает это на очередном событии
  хода, закрывает стрим — процесс провайдера гасится (тот же `finally`, что и при
  таймауте). Итог задачи — `canceled` (терминальное состояние).
- **Уведомления**: notify-send о завершении (неудача — всегда, успех — по желанию
  в будущих версиях; сейчас — оба, отключается `--no-notify`).
- Интервал опроса очереди — 2 с; без задач служба ничего не делает.

## Проверка

```sh
runneos-agents-service --once --no-notify   # вычистить очередь и выйти
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_service_agents.py' -v
```

## Границы

- Параллельных задач нет: служба выполняет по одной (журнал монотонен, ворота честны).
- Приоритетов нет — строго FIFO.
- Отмена между событиями провайдера не мгновенна: до ближайшего события стрима
  (для типичного хода — доли секунды).
