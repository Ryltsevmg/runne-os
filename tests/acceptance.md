# Приёмочные испытания Runne OS

> **Рабочая матрица для Arch + Niri + DMS.** Цели не являются результатами испытаний. Актуальные результаты записываются отдельно.

## Запуск приложений и окна
- [ ] Запуск приложения через поиск DMS, панель и горячую клавишу даёт одинаковый результат: если окно уже открыто — фокус на существующее окно.
- [ ] Новое окно открывается только отдельным явным действием.
- [ ] Escape в поиске возвращает фокус предыдущему окну, и набираемые символы попадают туда.
- [ ] Подключение дисплея не уводит окна за пределы экрана.
- [ ] Навигация между рабочими столами, окнами, колонками и мониторами соответствует сопоставлению в навыке.
- [ ] Переключение между окнами колонки и режим вкладок работают.
- [ ] Закрытие окна не завершает другие процессы приложения.

## Клавиатура
- [ ] Стандартные сочетания и универсальный буфер Super+C/X/V работают в RU/EN с правильными исключениями для терминала.
- [ ] Терминал, SSH, удалённый рабочий стол и ВМ сохраняют обычное поведение Ctrl.
- [ ] Активен только один ремаппер клавиш.

## Жесты
- [ ] Жесты следуют за пальцами и могут быть отменены.
- [ ] Прокрутка не переключает рабочие столы.

## Поиск
- [ ] Поиск показывает приложение и его открытые окна.
- [ ] Файлы находятся по имени.
- [ ] Точные совпадения ранжируются первыми.
- [ ] Опасные действия не выполняются при случайном нажатии Enter.
- [ ] Поиск по имени файла и по содержимому — разные, явно различимые режимы.
- [ ] Поиск строки из тестового файла `.env` ничего не находит.

## Буфер обмена и восстановление
- [ ] После повторного входа в сеанс тестовый пароль не находится в истории буфера обмена.
- [ ] Один файл восстанавливается из резервной копии Borg на чистой машине.
- [ ] 20 циклов сна и пробуждения — обязательно для образа и ноутбуков; ограничения minipc учитывать отдельно, статус «не проверялось» не считать успехом.

## Целевые показатели (из текста архитектуры)
- [ ] Вызов прогретого поиска: p95 до 150 мс на выбранном оборудовании; первый символ не теряется.
- [ ] Возврат фокуса: 30 циклов вызова и закрытия поиска без ввода в чужое окно.
- [ ] Сон и пробуждение: 20 циклов без потери сеанса, чёрного экрана и необходимости чинить устройства.
- [ ] Внешний монитор: 10 подключений и отключений без недоступных окон.
- [ ] Общение: проверенный 30-минутный звонок с демонстрацией экрана и сменой аудиоустройства.
- [ ] Эксплуатация: два проверенных полных обновления, испытанный откат и восстановленный файл.

## Интеграция Niri + DMS

- [ ] Чистый вход запускает Niri и ровно один экземпляр DMS.
- [ ] Spotlight, буфер и блокировка вызываются через DMS IPC.
- [ ] Запуск Ghostty из профиля Niri работает; конфигурация Ghostty проходит валидацию.
- [ ] Агент polkit показывает запрос авторизации и возвращает фокус после закрытия.
- [ ] Порталы выбора файла, секретов и демонстрации экрана работают.
- [ ] Исходники пакетов, собранные пакеты и установленное окружение используют один выбранный стек.
- [ ] Сочетания соответствуют стандарту RunneOS и не перехватываются глобальным remapper; пробелы указаны в справке навыка.

## DMS-плагины и AI Usage

- [ ] Закреплённые шесть плагинов восстанавливаются установщиком в чистом пользовательском сеансе; повторный запуск не создаёт дубликатов виджетов.
- [ ] US/RU: `ашкуащч` находит Firefox; `=2+2` показывает 4; `!` показывает окна и выбор переводит фокус.
- [ ] Print открывает Screenshot+, отмена возвращает фокус. Аннотации/копирование/сохранение корректны при разных масштабах и нескольких мониторах.
- [ ] Alt+Print: запись выбранного окна/экрана через portal; повторное нажатие останавливает. MP4 декодируется, системный звук и микрофон проверены отдельно.
- [ ] AI Usage показывает девять сервисов, отсутствующие данные имеют честный статус. Реальные балансы и квоты сверены с кабинетами каждого подключённого аккаунта.
- [ ] Обновление плагина и повторная установка сохраняют наш overlay; после нового входа DMS один, виджеты и IPC доступны.

## Агентная установка (решение владельца 2026-10-12: логин/пароль → агенты по умолчанию → агент настраивает остальное)

- [ ] Установщик задаёт ровно три вопроса: устройство (с подтверждением), имя пользователя, пароль; LUKS — выбором, а не меню из двадцати пунктов.
- [ ] `runneos-agents` и провайдерские CLI (codex, opencode) присутствуют в установленной системе без сети и без ручных команд.
- [ ] При первом входе в сеанс DMS firstboot-сценарий сам открывает панель агентов с агентом-настройщиком; пользователь не открывает терминал.
- [ ] Задачи агента-настройщика выполняются по политикам с аудитом: до подтверждения пользователем — только чтение; изменения системы — после явного согласия в интерфейсе.
- [ ] Неавторизованный провайдер отображается как «недоступен — подключить?» с переходом к штатному входу (ключ в GNOME Keyring), без ложных квот.
- [ ] Эталонный прогон: от носителя до настроенного сеанса (плагины DMS установлены, виджеты закреплены, `runneos-post-install --check` без проблем) — силами агента, без единой ручной команды в терминале.
